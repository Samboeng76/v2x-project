V2X specification, implementation, and test review
==================================================

<strong>Date:</strong> 2026-11-02<br><strong>Scope:</strong> The current working
tree of `Documentation/FormalSpecification.md`, `src/v2x_project`, the CLI entry
point, and `tests`. The J2735 submodule is out of scope. This review compares
the prototype with its own draft specification; it does not establish compliance
with the external SAE J2735 standard or a receiver implementation.

Review result
-------------

The main path is present: JSON5 configuration is validated, a fixed four-way MAP
layout and a SPaT batch are encoded as UPER, and both message types can be
decoded through the CLI. The CLI stages generated files before replacing
destinations. The tests exercise the sample configuration, selected invalid
inputs, fixed UTC generation, phase boundaries, decoding, and two
output-preservation cases.

The findings below distinguish observed defects from specification decisions and
coverage gaps. Severity describes impact within this project's stated scope.

Confirmed findings
------------------

### R1 — Extra bytes after a valid UPER message are accepted (medium)

<strong>Requirement:</strong> §5.1 and §5.2 describe decoding a complete
top-level `SPAT` or `MapData` message and rejecting data that cannot be decoded
as that message.

<strong>Evidence:</strong> Appending one full `00` byte to
`output/sample_map.txt` still made `decode_map` return intersection ID 42. The
same probe with the first line of `output/sample_spat.txt` made `decode_spat`
return intersection ID 42. In `src/v2x_project/core.py:689-718`, both decoders
call `from_uper` and inspect the decoded value, but do not verify that all input
bytes were consumed.

<strong>Effect:</strong> A corrupted or concatenated payload can be reported as
successfully decoded. Add a complete-consumption check that still permits legal
final-byte UPER padding, and test both decoders with valid and extra-byte
inputs.

### R2 — A missing file path is reported as invalid hex (medium)

<strong>Requirement:</strong> DEC-1 and MAP-DEC-1 accept file paths; ERR-7 asks
for useful file-access diagnostics for the SPaT decoder.

<strong>Evidence:</strong> `decode missing_file.txt --message-type spat` exits
nonzero but prints `invalid hexadecimal message: non-hexadecimal number ...`,
without identifying a failed file read. In `src/v2x_project/cli.py:316-356`, a
value that is not all hex is treated as a file only when `candidate.is_file()`
is true; otherwise it is passed to the hex decoder.

<strong>Effect:</strong> Users cannot tell whether they mistyped a path or
supplied bad hex. Treat a non-hex argument that looks like a path as a missing
or unreadable input file. Specify precedence for an existing file whose name
consists only of hex characters.

### R3 — SPaT summaries appear before JSON output succeeds (medium)

<strong>Requirement:</strong> ERR-7 says success output should follow a
successful write.

<strong>Evidence:</strong> Decoding one valid SPaT line with `--json-output
README.md/out.json` exits with status 2 because `README.md` is a file, but
standard output already contains a decoded-message summary.
`src/v2x_project/cli.py:350,356` prints summaries before `_atomic_json_write` at
line 370.

<strong>Effect:</strong> A failed decode command can appear partly successful.
Buffer the summaries and print them after the JSON write succeeds; keep
line-specific error reporting for partial file decodes.

### R5 — The two generation APIs handle naive times differently (low)

<strong>Requirement:</strong> §2.2 calls for a shared UTC time basis.

<strong>Evidence:</strong> `encode_map` immediately calls
`start_time.astimezone(timezone.utc)` (`src/v2x_project/core.py:594-595`), which
gives a naive Python `datetime` a host-local interpretation.
`generate_spat_messages` explicitly rejects naive datetimes
(`src/v2x_project/core.py:628-634`). The CLI itself supplies an aware UTC
datetime, so this affects direct Python callers rather than ordinary CLI use.

<strong>Effect:</strong> The same caller-supplied start time can encode MAP with
a machine-dependent timestamp while SPaT refuses it. Apply the same timezone
check to both functions, or explicitly define the direct API's naive-time
behavior.

### R6 — Very precise JSON5 coordinates can round differently from their literal value (low)

<strong>Requirement:</strong> §2.1.1 specifies nearest-unit coordinate
conversion, with exact halfway cases rounded away from zero.

<strong>Evidence:</strong> JSON5 literal `0.00000004999999999999999999` was
parsed as Python float `5e-08`. The implementation converts that float to
`Decimal(str(value))` in `src/v2x_project/core.py:143-173`, so scaling by
10,000,000 rounds to `1`. Scaling the literal decimal itself rounds to `0`.

<strong>Effect:</strong> Inputs extremely close to a rounding threshold can lose
their intended value before validation. Either preserve decimal text during
parsing or document a supported input precision and test its boundaries. This is
a low-likelihood issue for normal surveyed coordinates.

The tests in `tests/test_configuration.py`, `tests/test_generation.py`,
`tests/test_cli_behavior.py`, and `tests/test_map_decoder.py` are repeatable and
use temporary files for CLI output. They mainly cover the bundled sample
profile. There is no CI workflow or separate test runner configuration in this
working tree; the suite runs through standard-library `unittest`.

Recommended order of work
-------------------------

1. Fix R1–R3 and add regression tests for each observed decoder or CLI failure.
2. Correct the spec example (R4) and settle the three documentation details
   above before treating them as test requirements.
3. Add tests for the remaining profile boundaries, especially revision wrap,
   timestamp omission, coordinate and geometry edges, and the commit/rollback
   path. Exercise a successful `both` CLI run as an integration test.
4. Run an independent J2735 decoder on representative MAP and SPaT messages.
   Record its version and exact accepted payloads in the test evidence.
5. Address the 19 project-code Ruff findings before making lint a required gate;
   keep the generated submodule excluded from that gate.
